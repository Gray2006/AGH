# AGI 线：任务抽象

> 这是 AGH 从「审计工具」回到「AGI 命题」的唯一入口。
> 不解决它，进化/搜索那一半永远测不出东西。

## 为什么必须换

`docs/what-it-proves.md` 里的七条负面结果，根因只有一句话：

> **没有真模型会做错的题。**

五类难度尝试（纯函数、边界密集、单 bug、多 bug 模块、更大空间）全部失败——
`deepseek-v4.1-flash` 对 20 道题全对。种子在分数顶点，任何变异只减分，
所以「进化 vs 随机搜索」必然同分。

这不是搜索算法的问题，是**测量工具的分辨率不够**。
在一个人人满分的考试上，比较两种复习方法没有意义。

## 新任务族要满足什么

| 要求 | 为什么 | 怎么验 |
|---|---|---|
| **模型会做错** | 满分任务测不出差异 | 先跑基线：真模型通过率应显著 < 100% |
| **有部分分** | 全对/全错都没有梯度 | 通过率应在 10%–70% 区间 |
| **可自动判定** | 人工评分不可扩展 | 隐藏测试全过才算通过 |
| **可复现** | 结论要能被别人验 | 固定 base commit + 固定测试命令 |
| **不可作弊** | 候选不能看到答案 | 隐藏测试只在父进程，候选只见 issue 描述 |
| **够便宜** | 单轮预算 < 1 元 | 单任务 < 5000 tokens |

## 任务形态：仓库级修复

一道题 = **一个真实仓库的一个真实 bug**。

```
RepoTask
├── repo            仓库快照（含 .git，固定在 base_ref）
├── issue           给候选看的描述（自然语言 + 失败现象）
├── hidden_tests    判定用的测试命令（候选看不到）
└── timeout_s       超时即失败
```

**为什么是仓库级**：
- 需要读多个文件才能定位 → 上下文理解，不是背模板
- 需要跑起来才知道对不对 → 排除「看起来对」
- 有真实的边界和耦合 → `Case` 模型表达不了，这正是之前的天花板

## 判定流程

```
1. 复制仓库到临时目录（不动原仓库）
2. 候选产出补丁（unified diff）
3. git apply 补丁；失败 → 直接判不通过
4. 在临时目录跑 hidden_tests
5. 全绿 = 通过；否则不通过，附上输出
6. 无论成败，临时目录清理
```

**关键边界**：
- 候选**永远看不到** hidden_tests 的内容，只能看到 issue
- 判定在子进程里跑，超时即杀
- 补丁应用失败和不通过分开记，前者说明模型输出格式都不对

## 第一批任务从哪来

不自己造题（造出来的题又会被模型一次过）。用**历史提交**：

1. 找一个真实仓库（Python 优先，测试齐全）
2. 取一个「修了 bug 的提交」
3. base_ref = 它的父提交，hidden_tests = 仓库原有测试
4. issue = 该提交的 message + 可脱敏的失败现象

这样每道题都有：
- 确定的正确答案（那个提交）
- 确定的判定（原有测试必须全绿）
- 天然的难度分布（不同提交难度不同）

**先做一个仓库、10 道题**，跑基线看通过率。通过率 100% → 换更难的任务；
通过率 0% → 太难以至没有梯度。落在 10%–70% 才算可用。

## 成功判据

| 阶段 | 判据 |
|---|---|
| 1. 基线 | 真模型在 10 道题上通过率落在 10%–70% |
| 2. 有梯度 | 同批任务，两次不同策略的通过率差 > 噪声 |
| 3. 进化有效 | 档案式进化 > 随机搜索，配对检验显著 |
| 4. 可外推 | 换一个仓库仍成立 |

停在阶段 1 也是结论：如果换到真实仓库任务后模型还是接近满分，
那「搜索无用」这个负面结果就从「题库人工产物」升级成了「真实任务上也成立」，
价值比现在高得多。

## 与审计层的关系

不冲突，是上下两层：

- **审计层**（已完成）：记录每一次调用、证明没被改、可重放
- **AGI 层**（本条线）：用真实任务测「多智能体协作 + 搜索」到底有没有用

而且审计层正好是 AGI 层需要的基础设施——每道题的每次尝试都会被哈希链记录下来，
可以回答「这次提升是真的还是随机波动」。
